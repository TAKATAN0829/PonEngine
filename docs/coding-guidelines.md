# コーディング規約

## 見出し

処理のまとまりを、次の4段階で表す。

| 階層 | 区切り線の目安 | 例 |
|---|---|---|
| 大見出し | 102列目 | 初期化処理・更新処理・描画処理・終了処理 |
| 中見出し | 52列目・上下の線で挟む | モデル初期化・Particle初期化 |
| 小見出し | 27列目 | メインモデル・サブモデル |
| 見出し | 区切り線なし | 設定・データ読み込み・生成・Scene登録 |

区切り線の直下に `// ○○` と見出しを書く。列位置はインデントを含めて確認し、余計な `=` を追加しない。以下の例ではタブ幅4で、区切り線直後のカーソルが102・52・27列目になる。

```cpp
//=================================================================================================//
// 初期化処理

void GameScene::Initialize(const SceneContext& context) {

	//===========================================//
	// モデル初期化
	//===========================================//

	//==================//
	// メインモデル

	// 設定
	modelColor_ = {1.f, 1.f, 1.f, 1.f};
	enableLighting_ = true;
	shininess_ = 40.f;

	// データ読み込み
	ModelManager::GetInstance()->LoadModel("plane.gltf");

	// 生成
	model_ = new Object3d();
	model_->Initialize(object3dCommon_);

	//==================//
	// サブモデル

	// 設定
	subModelColor_ = {1.f, 1.f, 1.f, 1.f};
}
```

- 「モデル初期化」という中見出しの中を、小見出しの「メインモデル」「サブモデル」に分ける。別々の中見出し「メインモデル初期化」「サブモデル初期化」にはしない。
- 小見出し内でも処理が長い場合は、区切り線のない見出しで細分化する。
- 中見出しは同じ長さの区切り線を上下に置き、3行のボックスにする。大見出し・小見出しには下の区切り線を付けない。
- 「メインモデル / 設定」のように複数の階層を1行へ詰め込まない。

## 処理の配置と空行

- 対象ごとに処理をまとめる。メインモデルの設定・読み込み・生成の途中へ、サブモデルの処理を混ぜない。
- 宣言・初期化・更新・描画・解放で、対象の区切り方を揃える。
- 同じ見出しに属する一連の文は続けて書き、処理のまとまりの間に空行を入れる。
- すべての文の間へ機械的に空行を入れない。
- 区切り線を伴う見出しと本文の間には空行を入れる。区切り線のない見出しは直下から処理を書く。

## 初期化

- `.h` はメンバーや関数の宣言を置く。メンバーの初期値をヘッダーへ書かない。
- 初期値は `.cpp` の `Initialize()` で、対象ごとにまとめて設定する。
- 追加時に生成するデータは、`AddModel()` など、その生成処理で初期値を設定する。
- `Initialize()` を必要とするクラスは、更新・描画・モデル追加などで使う前に初期化する。
- 初期化の場所を変える際は元の初期値を保ち、各メンバーが使用前に設定されることを確認する。

## 条件分岐

- 三項演算子 `条件 ? 値 : 値` は使わず、`if` で分岐を明示する。
